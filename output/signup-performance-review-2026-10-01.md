# Signup and entry performance, 2026-10-01

This review used local source and the existing build. It did not measure production latency, create accounts, contact providers, rebuild, or run Miniflare. There is no measured evidence here that Cloudflare hosting causes the reported delay.

## Implemented and checked

- `app/turnstile-loader.ts:3`, `app/auth-panel.tsx:118`: start the Turnstile script and public configuration request concurrently when a protected account form opens. Previously the configuration had to complete before the widget started downloading the script. The widget still shares the same script promise and owns script retries. Configuration remains action-checked, uses a 10-second deadline, ignores obsolete responses, and exposes an explicit retry. Captcha, OTP, MFA, password checks and provider validation are unchanged.
- `build/workspace-style-anchors.json`, `app/layout.tsx`, `app/workspace-base-styles.ts`, `app/workspace-styles.ts`: restore 17 now-shared public CSS anchors and put the shared chart controls in the public projection. The original full stylesheet still loads before workspace rendering. The six isolated sheets that formerly preceded dashboard-explorer contain no competing explorer/greeting selectors.
- Original style/chart suite: 30/30 passed. Added real-CSS projection regression: all 5 style tests passed. Signup, Turnstile, browser-session and interaction checks: 58/58 passed. Focused lint passed. Typecheck encountered concurrent changes outside this slice: executive-overview sampleEmpty prop and billing/synchronize nullable attempt. Root was notified.

## Remaining opportunities, in priority order

1. **Combine entry reads under one authenticated bootstrap contract.** `app/page.tsx:108,329`, `app/session-timeout.tsx:62,93`, `app/legal-acceptance-gate.tsx:32,73`, `app/billing-onboarding-gate.tsx:71`: completed-workspace entry serializes onboarding, session lease, legal acceptance and entitlements before the application mounts. Each protected endpoint verifies the user against Supabase (`server/api.ts:48-95`). The nested gates also defer discovery of later lazy chunks. A consolidated read can verify identity and membership once, then read the required lease/legal/entitlement state together. Preserve server authorization, fresh revocation checks, no-store responses, legal-version checks and user-switch cancellation. Prefetching code on explicit auth intent is separate from fetching private data.
2. **Remove duplicated validation inside the onboarding billing GET.** `app/api/v1/billing/route.ts:15-24` runs requireIdentity/findAccessContext, then requireBillingAccess repeats both for an existing workspace. The latter still must enforce owner/admin, deletion/session rules and billing permission. Refactor to share the already verified identity/context within this request only; do not add a cross-request token or permission cache. The subscription/addon reads at lines 25-28 also overlap getTenantEntitlements/subscriptionSnapshot (`server/entitlements/engine.ts:174,196`).
3. **Bound billing reads and retry sessions.** `app/billing-onboarding-gate.tsx:71-88,108-166,168`: GETs currently have no abort deadline. A stalled request keeps the access screen waiting and the automatic inFlight flag set. Manual refresh is a separate path and can overlap it. Payment success makes up to 21 checks spaced 1.5 seconds apart; focus/visibility and the 60-second interval restart that attempt counter. Share one cancellable read, retain the last safe UI state, provide retry, and keep a single bounded confirmation budget. Payment access must still come from server-confirmed state. Do not automatically retry checkout mutations without their existing idempotency contract.
4. **Measure the homepage's eager graph, not only the auth dialog.** The existing build at `2026-10-01T08:43:24.002Z` has 23 transitive eager homepage JS chunks: 846,487 bytes raw and 253,517 bytes summed independent gzip. Opening auth adds 5 chunks: 27,067 raw and 9,224 gzip. The Supabase chunk is 209,253 raw / 53,767 gzip; the shared executive-overview chunk is 66,244 / 18,938. These are artifact sizes, not measured network transfer or execution times. `app/page.tsx:17,30,206` eagerly includes the interactive homepage preview and auth SDK and checks the session before opening query-requested signup. Consider deferring below-fold previews while preserving accessible static examples and test direct signup separately from homepage browsing. Root owns that surface.
5. **Keep required waits honest and separately timed.** Password exposure checking is an external, fail-closed request capped at 8 seconds (`shared/password-exposure.ts:7-34`, `app/auth-panel.tsx:182`). Signup itself goes directly to Supabase, email delivery is another provider path, and enrollment uses multiple Supabase MFA requests (`app/founder-mfa-gate.tsx:37-90`). Do not remove these safeguards or their cleanup verification to claim faster signup. Current loading copy can identify the active stage without logging credentials or identity data.

## Test and measurement strategy

- Browser timings: cold and warm visits, direct `?start=signup`, homepage-to-signup, OTP verification-to-MFA, MFA-to-billing, return-from-checkout and setup-to-workspace. Record total and individual resource/API durations, request counts, LCP/INP/CLS, device/network profile and cache state. Capture only aggregate timing, never passwords, tokens, email codes, VIN/customer data or request bodies.
- API refactor regression: count auth-provider calls for one billing/bootstrap request; separate requests must still reverify. Cover missing/expired session, AAL1, changed membership, revoked lease, deleted account, owner/admin/employee permissions, policy version changes, unpaid/complimentary/internal/subscription access and switching users mid-request.
- Retry tests: hung configuration/read, timeout, late response, abort on unmount/user switch, concurrent refresh/focus, confirmed-payment transition and exhausted retry budget. Preserve idempotent checkout and webhook convergence tests.
- Existing test targets: `tests/turnstile-loader.test.ts`, `tests/browser-session.test.ts`, `tests/signup-funnel.test.ts`, `tests/signin-flow.test.mjs`, `tests/onboarding-identity-recovery-flow.test.mjs`, `tests/subscription-access-flow.test.ts`, `tests/session-policy.test.ts`, `tests/workspace-style-loading.test.ts`. Run Worker integration tests serially only after the next stable build.
