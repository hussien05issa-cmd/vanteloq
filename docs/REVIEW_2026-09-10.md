# Vanteloq project review — September 10, 2026

Vanteloq is an operating-intelligence application for independent retailers. It combines approved commerce records, financial context, purchasing, marketing measurement and assigned work. BookLoQ is its separate accounting workspace. The product uses a shared calculation and authorization layer rather than giving an AI unrestricted database access.

## Architecture and connections

- **Application and hosting:** React with Vinext/Vite, deployed as a Cloudflare-compatible Worker through the existing Sites project at vanteloq.com.
- **Business database:** Cloudflare D1 with versioned Drizzle migrations. Business records are scoped by workspace and, where applicable, location. Role permissions are enforced on the server.
- **Identity:** Supabase authentication, email recovery, session controls and required multifactor assurance for protected access. Resend is the configured authentication email sender. Password recovery was repaired earlier in this session and the owner confirmed receiving the email.
- **Documents:** R2 storage with quarantine, MIME/signature checks, bounded upload size, duplicate detection and permission checks. Malware scanning and OCR still require operational configuration; this review did not release quarantined customer documents.
- **Billing:** Stripe subscription billing and entitlements are distinct from merchant payment-source connections.
- **AI:** Gemini and OpenAI are called only from the server after explicit versioned consent. Provider selection is transmitted with every request. Both mode gives separate attributed analyses, not a claim that agreement proves accuracy.

## Changes in this release

1. Redesigned Vanteloq AI as a focused commerce chat with responsive layout, clearer provider controls, formatted tables/lists and an animated blue-purple brand mark. Thinking and deletion states are distinct. Reduced-motion preferences are respected.
2. Suggested questions can be hidden and reopened. Choosing a suggestion collapses the list; active conversations do not keep the welcome suggestions on screen.
3. Memory defaults off each time the AI workspace opens. With memory off, requests contain no conversation history and new question/reply content is not stored in the chat tables. With memory on, up to six messages are reused only when evidence, provider, user, workspace and access still match. Changing memory or provider resets the consent choice and starts a fresh chat.
4. Saved-chat controls list dates without exposing old question content. Users can delete individual saved chats or all their saved chats in the current workspace after confirmation. Deletion is scoped on the server and does not require an AI subscription or current insights permission. Content-free audit metadata remains. Provider safety logs and managed backups have separate retention.
5. Added a specialized business-analysis instruction set for finance, KPI interpretation, marketing funnels, inventory, cash and risk. It uses server-calculated KPIs, labels assumptions, avoids false causal or profitability claims, and explains unsupported domains. Instructions are sent separately from untrusted questions and evidence. No automated business-action tools are granted to the models.
6. Corrected provider selection transport. Previously the UI selection could be omitted, allowing the backend default to determine the provider.
7. Stale sales imports no longer generate an apparently current seven-day forecast. Payment mix and period context identify the latest verified date/window.
8. Missing stock records now remain unknown instead of becoming zero stock. Purchasing marks these products for input review and withholds reorder/cash-allocation conclusions. Failed purchasing loads provide an explicit retry state.
9. Replaced Unix-dependent development/build/test entry points with portable Node scripts for the Lenovo transfer. Test commands reject nonexistent test files.
10. Updated Next.js, React/RSC, Vinext, Vite, MapLibre GL and related dependencies to patched releases. Pinned patched sharp, undici, ws and esbuild overrides also cover build-tool dependency chains. The final full npm audit, including development dependencies, returned **zero known advisories** (669 total dependencies). This is a registry dependency check, not proof that the whole product is vulnerability-free. Vinext remains a beta runtime; build and application regression checks are required for subsequent upgrades.
11. Corrected data-quality labels for a location-restricted view. Workspace-wide connections, documents and import counts withheld by scope now say “Outside scope” instead of implying zero records or no provider. Loading failures provide a retry state.

## Verification and limits

The review covers the public site and primary workspace navigation, deterministic calculations, compiled Worker behavior, database migrations, tenant and location isolation, provider transport, consent enforcement, deletion, memory boundaries, billing/permissions, integration fixtures and document quarantine. Browser interaction verifies suggestions and consent reset with fictional data; integration tests verify actual database outcomes with isolated test identities and intercepted provider responses.

All 24 BookLoQ navigation areas were also opened, including banking, reconciliation, ledger, invoices/bills, payroll, tax, assets, reports, month-end and accountant access. Unavailable exports, production banking and accounting automations remain labelled; opening these views does not establish end-to-end financial execution. Desktop and 390-pixel mobile AI layouts were inspected. The final patched build, TypeScript, lint and read-only Drizzle migration consistency check passed.

No customer money was moved, advertising was published, business email was sent, customer document was released, or production record was deleted during this review. A production concurrency/load test, disaster-recovery restore, independent penetration test and legal sign-off have not been established.

**Operational work still required:** securely activate OpenAI; verify Gemini paid-service billing; complete desired production connector approvals and reconciliation; configure and validate scanning/OCR if document release is required; finish durable queue/retry operations; verify account-level backups, monitoring and restore procedures. A real-model business-quality evaluation remains necessary after provider activation. The specialized playbook and deterministic evidence controls are implemented, but model answer quality cannot be certified while providers are blocked.

The formal Codex Security scan failed before receiving a scan ID because its launcher could not inspect a Windows npm-cache file. Its desktop workflow explicitly says: “If the direct start fails or returns malformed context, surface that error.” It also forbids starting a replacement scan or switching to a terminal scan workflow. Consequently no completed formal source-security scan is claimed here. Ordinary implementation checks and the npm dependency audit are recorded separately.

## Privacy sources checked

The consent design makes the data, purpose, recipient and choice visible, consistent with the [Canadian privacy commissioner's meaningful-consent guidance](https://www.priv.gc.ca/en/privacy-topics/privacy-for-businesses/appropriate-handling-of-personal-information/collecting-personal-information-and-consent/consent/gl_omc_201805/). Whether the business meets every applicable legal obligation also depends on its operations, contracts and jurisdiction.

OpenAI requests use `store: false`; that does not erase separate provider safety retention. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data). Gemini confidential-data use stays gated pending paid-service verification because the [Gemini API terms](https://ai.google.dev/gemini-api/terms) distinguish unpaid and paid processing.
