## Official sources and interpretation limits

- **A1, Apple Motion:** [Human Interface Guidelines: Motion](https://developer.apple.com/design/human-interface-guidelines/motion). Official indexed text retrieved during research supports purposeful, optional, brief feedback and allowing interaction without waiting for animation. Direct page retrieval returned the JavaScript shell, so this was verified from the search index of Apple's official page, not a browser rendering.
- **A2, Apple reduced motion:** [Reduced Motion evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/reduced-motion-evaluation-criteria). Discusses optional alternatives for motion triggers and respecting system settings. This is Apple app evaluation guidance, not a web conformance standard.
- **W1, labels:** [W3C WAI: Labeling Controls](https://www.w3.org/WAI/tutorials/forms/labels/). Explicitly associate labels with controls; keep their visual relationship clear. Labels above fields can reduce horizontal scrolling, subject to the whole design.
- **W2, errors:** [W3C WAI: User Notifications](https://www.w3.org/WAI/tutorials/forms/notifications/). Use corrective field-specific errors, error summaries with links, associated descriptions, and appropriate first-error focus after submission.
- **W3, status:** [WCAG 2.2 Understanding 4.1.3: Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Status changes need programmatically determinable roles or properties so assistive technology can announce them without receiving focus. This criterion is Level AA.
- **W4, visible focus:** [WCAG 2.2 Understanding 2.4.7: Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html). Keyboard users need an identifiable focus indicator. This criterion is Level AA.
- **W5, obscured focus:** [WCAG 2.2 Understanding 2.4.11: Focus Not Obscured (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html). Level AA prohibits author-created content entirely hiding a focused component. Keeping it fully visible is the stronger local implementation target.
- **W6, reduced motion:** [WCAG technique C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39) and [Understanding 2.3.3: Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html). Static styles with opt-in `no-preference` animation are a documented approach. SC 2.3.3 is Level AAA; C39 is a sufficient technique, not a mandatory CSS prescription.
- **W7, targets:** [WCAG 2.2 Understanding 2.5.8: Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Level AA uses a 24 by 24 CSS-pixel target or qualifying spacing/other exceptions. Vanteloq's larger 44/48 px policy is the approved product direction.
- **W8, reflow:** [WCAG 2.2 Understanding 1.4.10: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html). Verify vertical content at 320 CSS px without loss of information/function or two-dimensional scrolling, allowing the criterion's exceptions for content that requires two dimensions.
