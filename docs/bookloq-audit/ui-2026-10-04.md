## Concrete defects and behavior mismatches

These findings are demonstrated by the handlers or data path, not by a browser test. Prioritize them before adding more panels.

1. **Source search does not search source fields (category 6).** The transaction search placeholder promises “merchant, customer, category or source.” The predicate at [398](../work/vanteloq/app/bookloq-workspace.tsx#L398) includes description, original description, contact and account name, but excludes `sourceSystem` and `externalSourceId`; the placeholder is at [414](../work/vanteloq/app/bookloq-workspace.tsx#L414). Add those fields or narrow the promise. Acceptance: searching a provider or exact external reference finds its permitted record even when that text is absent from the description.
2. **“Review” performs an evidence match immediately (category 6).** Receipt candidates at [466](../work/vanteloq/app/bookloq-workspace.tsx#L466) display “Review” but call `match("receipt", document.id)`, whose handler posts `match_transaction` at [461](../work/vanteloq/app/bookloq-workspace.tsx#L461). There is no intervening document preview. Open the actual evidence first, then use an explicit “Confirm match” action. Existing server confirmation remains mandatory.
3. **Full-history wording exceeds the loaded transaction window (category 6).** The UI offers “All imported history” and exports the filtered in-memory array, while the endpoint returns at most 1,000 transactions. Older rows cannot be reached from this list. [UI filters/export, 398](../work/vanteloq/app/bookloq-workspace.tsx#L398), [wording, 415](../work/vanteloq/app/bookloq-workspace.tsx#L415), [query cap, 165](../work/vanteloq/app/api/v1/bookloq/route.ts#L165). Add server pagination/counts and server-scoped exports; until then label the loaded window truthfully.
4. **Budget modal omits the established dialog accessibility pattern (category 2, source-confirmed accessibility gap).** [BudgetComposer, 655](../work/vanteloq/app/bookloq-workspace.tsx#L655) uses a modal-shaped div and form without dialog role, accessible dialog name, or `useModalFocus`; the invoice and journal composers already use it at [562](../work/vanteloq/app/bookloq-workspace.tsx#L562) and [783](../work/vanteloq/app/bookloq-workspace.tsx#L783). Reuse that pattern and give its close control an accessible name. Keyboard behavior remains to be verified in a browser.
5. **Settings presents a default jurisdiction as if configured (category 2, misleading fallback).** [770](../work/vanteloq/app/bookloq-workspace.tsx#L770) substitutes `CA-AB` when settings are absent and zero for an absent cash safety threshold. Display “Not configured” and a setup action; do not imply a selected province or reviewed reserve amount.
6. **Accountant invitation copy needs reconciliation with existing platform capability (category 2).** [754](../work/vanteloq/app/bookloq-workspace.tsx#L754) says invitations remain unavailable until identity invitations are implemented, while a team-invitation route already exists. A safe finance-specific invitation flow is still incomplete, but its copy should describe the missing integration/scope, not assert the entire identity capability does not exist.

No new claim is made that PDF invoice generation, banking, journal balancing, reconciliation mathematics, tax arithmetic, customer authentication, or publication is broken. Those require their own acceptance checks and, where applicable, provider credentials.

## Permissions, plans, setup, and scope

- **Preserve server enforcement (category 1).** BookLoQ entry points require organization access, BookLoQ entitlement, feature access and finance permissions; mutation handlers separately check their action. Sources: [read gate, 88](../work/vanteloq/app/api/v1/bookloq/route.ts#L88), [actions, 31](../work/vanteloq/app/api/v1/bookloq/actions/route.ts#L31), [invoice gate, 29](../work/vanteloq/app/api/v1/bookloq/invoices/route.ts#L29), [journal gate, 49](../work/vanteloq/app/api/v1/bookloq/journals/route.ts#L49), [action-to-feature mapping, 58](../work/vanteloq/domain/paid-feature-routing.ts#L58).
- **Reconcile the two permission vocabularies (category 3).** The platform has custom role permission records and an accountant/bookkeeper template; BookLoQ also derives a legacy permission set from owner/admin/manager/employee/read_only/integration and intersects selected capabilities. Do not replace either by a presentation-only toggle. Review the full matrix before adding AR-only/AP-only or custom finance roles. Sources: [BookLoQ legacy roles, 15](../work/vanteloq/server/bookloq.ts#L15), [platform role templates, 186](../work/vanteloq/server/permissions.ts#L186), [effective custom permissions, 247](../work/vanteloq/server/permissions.ts#L247), [UI intersection, 367](../work/vanteloq/app/api/v1/bookloq/route.ts#L367).
- **Keep entitlement controls but improve explanations (category 2).** The outer navigation retains locked states, standalone finance routing and upgrade notices. Internal destinations are permission-filtered; action feature gates can still deny a visible action. Show the relevant access requirement close to the action and retain server checks. Sources: [outer navigation and entitlement handling, 964](../work/vanteloq/app/vanteloq-app.tsx#L964), [navigation item, 1134](../work/vanteloq/app/vanteloq-app.tsx#L1134), [authorized sections, 198](../work/vanteloq/app/bookloq-workspace.tsx#L198).
- **Onboarding is not missing wholesale (category 3).** Existing setup covers business/industry, jurisdiction/address, currency/reporting preferences, fiscal year start, tax identifier, source intention, overview preferences, saved progress and empty workspace creation. It does not complete the brief's accounting basis/chart template/opening balances/migration/reconciliation/accountant invite chain. Sources: [setup shape, 37](../work/vanteloq/app/secure-onboarding-flow.tsx#L37), [saved draft, 147](../work/vanteloq/app/secure-onboarding-flow.tsx#L147), [jurisdiction, 397](../work/vanteloq/app/secure-onboarding-flow.tsx#L397), [fiscal year, 506](../work/vanteloq/app/secure-onboarding-flow.tsx#L506), [sources, 649](../work/vanteloq/app/secure-onboarding-flow.tsx#L649), [first actions, 247](../work/vanteloq/app/bookloq-workspace.tsx#L247).
- **Location scope exists, but dimensions are incomplete (category 3, 5).** The read API validates requested location and restricts organization-wide access. The UI shows scope boundaries. Journal and invoice payloads hardcode `locationRef: "all"`; budget composition hardcodes both location and department. The collections component does not accept the active location prop and requests organization document balances. Keep that distinction explicit within a location-selected workspace. Sources: [scope validation, 97](../work/vanteloq/app/api/v1/bookloq/route.ts#L97), [scope banner, 235](../work/vanteloq/app/bookloq-workspace.tsx#L235), [collections request, 43](../work/vanteloq/app/bookloq-collections.tsx#L43), [invoice payload, 582](../work/vanteloq/app/bookloq-workspace.tsx#L582), [budget payload, 666](../work/vanteloq/app/bookloq-workspace.tsx#L666), [journal payload, 795](../work/vanteloq/app/bookloq-workspace.tsx#L795).
- **Search is navigation-only at both levels (category 3, 8).** BookLoQ search filters section labels/groups. The global command palette filters available workspaces, not customer/invoice/bill/transaction records and not executable commands. The local collections search is a separate working record search. ## Responsive design and accessibility source review

The active design is layered: older compact `bookloq.css` values are overridden by `workspace-design.css`, then component styles. Do not diagnose the old 6–8px declarations as the effective production text size without considering the cascade. Current workspace overrides set body/labels to 14px, supporting text to 12px, controls to readable sizes, and finance rail width to 220px. Sources: [global type, 51](../work/vanteloq/app/workspace-design.css#L51), [BookLoQ scope, 344](../work/vanteloq/app/workspace-design.css#L344).

- BookLoQ's secondary rail becomes a grouped select in constrained layouts; the review stylesheet also applies an earlier 1400px breakpoint. This preserves navigation but reduces visible wayfinding. Use one predictable breakpoint rule and a clearly labeled section switcher. [Workspace responsive rules, 413](../work/vanteloq/app/workspace-design.css#L413), [review responsive rules, 212](../work/vanteloq/app/bookloq-review-workflow.css#L212).
- Collections has two-column KPIs on smaller screens, stacked content, scrollable 570px record tables and a single-column filter form. Later KPI rules use container-relative font size and local horizontal amount scrolling. Test long CAD values, localized labels and zoom rather than replacing amounts with clipped strings. [Collections stylesheet, 8](../work/vanteloq/app/bookloq-collections.css#L8), [narrow rules, 10](../work/vanteloq/app/bookloq-collections.css#L10), [amount rules, 17](../work/vanteloq/app/bookloq-collections.css#L17).
- Generic financial tables use a 740px minimum width; transactions use 900px. Horizontal scrolling is appropriate for dense detail but should have an accessible label and visible affordance. The transaction region is keyboard focusable; generic tables only expose table semantics and an overflow wrapper. [Generic table, 839](../work/vanteloq/app/bookloq-workspace.tsx#L839), [table CSS, 10](../work/vanteloq/app/bookloq.css#L10).
- Invoice layout collapses to single columns at 760px; budget/date and receipt layouts stack below 700px. Journal and invoice dialogs already use the shared focus helper. Apply the same pattern to budget and record-source dialogs. [Composer CSS, 32](../work/vanteloq/app/bookloq.css#L32), [budget/receipt narrow rules, 41](../work/vanteloq/app/bookloq.css#L41).
- Full-screen finance expands the existing workspace and preserves state; Escape restores the display button unless a dialog/select is active. Keep this behavior. [Escape handling, 203](../work/vanteloq/app/bookloq-workspace.tsx#L203), [display stylesheet, 13](../work/vanteloq/app/bookloq-display.css#L13).
- Collections and cash visuals have reduced-motion rules, visible focus and some forced-colors handling; review UI includes reduced-transparency/forced-colors accommodations. Preserve them through the visual refinement. [Collections, 2/11](../work/vanteloq/app/bookloq-collections.css#L2), [cash visuals, 60](../work/vanteloq/app/bookloq-dashboard-visuals.css#L60), [review accessibility, 242](../work/vanteloq/app/bookloq-review-workflow.css#L242).

## Top improvements, preserving the existing functions

1. **Repair misleading actions and incomplete history first.** Fix source search, split receipt preview from match confirmation, disclose/paginate loaded windows, correct absent-settings fallback, and apply the shared dialog pattern to budgets. These are narrow fixes with clear acceptance criteria above.
2. **Create one financial home with exact source routes.** Keep collections as a major section, but show cash, revenue, expenses, net earnings/gross profit, AR/AP and tax availability up front. Preserve current definitions and distinguish posted ledger, document balances, bank balances and forecast. A single period/scope bar must not relabel cumulative numbers as period results.
3. **Introduce stable finance route state.** Group existing destinations under Overview, Money, Sales, Purchases, Accounting, Reports, Taxes, Planning, AI and Settings. Preserve aliases and permissions. Add record ID, period, basis, scope and return context to navigation. Consolidate Sales/Invoicing presentation without removing either entry path during migration.
4. **Standardize the evidence drawer.** Reuse private document viewing and transaction review; include original source, attachments, links, accounting impact, approval/history and explicit confirm actions. Make every supported KPI/report amount open its exact contributing records. Do not turn an unverified document or matched bank row into posted accounting automatically.
5. **Finish a real reconciliation workflow.** Reuse the reviewed statement import, category review, candidate matching and existing record history. Add account/period selection, ledger comparison, clear difference causes, reviewed resolution, completion and protected reopening. Import validation and equality of balances alone do not prove reconciliation.
6. **Complete financial settings and setup before broader accounting automation.** Reuse existing onboarding, identity, roles and integrations. Expose reviewed accounting policy, fiscal periods, COA and opening balances with clear unavailable states and protected changes. Resolve the legacy/custom permission matrix as part of this work.
7. **Expand existing AR/AP workflows in place.** Keep invoice PDF/email and collections follow-up. Add record detail/status controls, approved bill creation, contacts, partial-payment evidence, credit/recurring lifecycles and purchase-document links according to backend support. Keep actual payment execution separate and unavailable until fully integrated.
8. **Build reporting on server calculations and traceable dimensions.** Start with period/basis-filtered P&L, balance sheet, trial balance and GL with drilldowns, then add aging, tax, budget and dimension reports. Preserve exact CSV values and permission checks. Avoid a custom-report builder before its metric definitions and source routes are sound.
9. **Make the accountant mode a coherent experience.** Expose account/journal/period tools, blockers, reconciliations, evidence and sign-off together. Add an owner mode with clearer labels and optional explanations; both use identical data and security. Replace opaque “books health” presentation with transparent readiness components.
10. **Connect cash planning, budgets and AI through reviewed assumptions.** Reuse current 13-week and operational forecasts. Make fact/calculation/forecast/recommendation explicit, show input freshness and missing coverage, and link each assumption to records. Require review before any financial mutation; no autonomous posting or manufactured confidence.

No competitor research or current tax-law verification was undertaken in this UI audit. The brief's QuickBooks/Xero/Zoho/FreshBooks/Sage/Wave benchmark and jurisdiction work remain subsequent research tasks, not evidence that this implementation has feature parity or filing readiness.
